# ابرسرور — سامانه فروش سرور مجازی

فروشگاه و پنل مدیریت سرور مجازی، دوزبانه (فارسی/انگلیسی) با Next.js و PostgreSQL.

> **A bilingual VPS hosting storefront and admin panel.** Persian (RTL) and
> English (LTR), built with Next.js App Router, TypeScript, Tailwind and Prisma.

---

## نصب یک‌خطی

```bash
curl -fsSL https://raw.githubusercontent.com/MAHDI-byte64/Vps-sell/claude/compassionate-lovelace-4rr7wk/install.sh | bash
```

همین یک خط کد را clone می‌کند، وابستگی‌ها را نصب می‌کند، رمزهای امنیتی
واقعی می‌سازد، PostgreSQL را بالا می‌آورد، جدول‌ها و داده‌های اولیه را
می‌سازد و سایت را روی <http://localhost:3000> اجرا می‌کند.

> اجرای اسکریپت از اینترنت با `| bash` را همیشه اول بخوانید. محتوای آن در
> همین مخزن، فایل [`install.sh`](install.sh) است.

اگر مخزن را از قبل clone کرده‌اید، از داخل همان پوشه:

```bash
./install.sh
```

**گزینه‌ها**

| گزینه | کار |
|---|---|
| `--prod` | به‌جای سرور توسعه، بیلد production بگیر و اجرا کن |
| `--no-start` | همه‌چیز را آماده کن ولی سرور را بالا نیاور |
| `--db-url <url>` | به‌جای PostgreSQL داکری، از دیتابیس خودت استفاده کن |
| `--dir <path>` | مسیر clone (پیش‌فرض: `vps-sell`) |
| `--help` | راهنما |

مثال با دیتابیس خودتان:

```bash
./install.sh --db-url postgresql://user:pass@host:5432/dbname --prod
```

اجرای دوباره امن است: فایل `.env` موجود هرگز بازنویسی نمی‌شود (چون عوض شدن
`CREDENTIAL_SECRET` رمز همه سرورهای ذخیره‌شده را غیرقابل بازیابی می‌کند) و
داده‌های اولیه upsert می‌شوند، پس داده‌های شما از بین نمی‌رود.

### راه‌اندازی دستی

اگر ترجیح می‌دهید مرحله‌به‌مرحله جلو بروید:

```bash
npm install
cp .env.example .env
# در .env مقدارهای AUTH_SECRET و CREDENTIAL_SECRET را عوض کنید:
#   openssl rand -base64 48
docker compose up -d db
npm run setup
npm run dev                  # توسعه، روی http://localhost:3000
npm run build && npm start   # نسخه production
```

### حساب‌های اولیه (پس از `npm run setup`)

| نقش | ایمیل | رمز |
|---|---|---|
| مدیر | `admin@vpssell.local` | `Admin@12345` |
| مشتری نمونه | `demo@vpssell.local` | `Demo@12345` |

این مقادیر در `.env` قابل تغییرند (`SEED_ADMIN_EMAIL` و `SEED_ADMIN_PASSWORD`).
**پیش از انتشار عمومی حتماً عوضشان کنید.**

## امکانات

### بخش عمومی
- صفحه اصلی، لیست پلن‌ها با فیلتر نوع/لوکیشن/دوره پرداخت
- صفحه پیکربندی و سفارش هر پلن (لوکیشن، سیستم‌عامل، دوره، تعداد، نام میزبان)
- بلاگ با Markdown، سوالات متداول، درباره ما، تماس با ما
- دوزبانه کامل با RTL/LTR خودکار و سوییچ تم تیره/روشن

### پنل کاربری
- **سرورهای من** — اطلاعات ورود (آی‌پی، نام کاربری، رمز)، تمدید، تمدید خودکار
- **فاکتورها** — مشاهده، پرداخت، چاپ
- **کیف پول** — شارژ حساب و تاریخچه تراکنش‌ها
- **تیکت پشتیبانی** — با دپارتمان، اولویت و اتصال به سرویس
- **حساب کاربری** — ویرایش مشخصات و تغییر رمز

### پنل مدیریت
- داشبورد درآمد و کارهای نیازمند رسیدگی
- **تحویل سرور** — ثبت آی‌پی و رمز (رمزنگاری‌شده) و فعال‌سازی سرویس
- تأیید یا رد پرداخت‌های کارت‌به‌کارت
- مدیریت سفارش‌ها، فاکتورها، کاربران (نقش، فعال/غیرفعال، اصلاح موجودی)
- مدیریت پلن‌ها، کدهای تخفیف، مطالب بلاگ
- تنظیمات سایت (نرخ دلار، مالیات، تخفیف دوره‌ها، اطلاعات تماس)

## معماری و تصمیم‌های مهم

**واحد پول.** همه مبالغ به‌صورت عدد صحیح **تومان** ذخیره می‌شوند. نسخه
انگلیسی همان اعداد را با نرخ دلار قابل‌تنظیم در پنل مدیریت نمایش می‌دهد.
یک ارز تسویه یعنی دفتر کیف پول همیشه با تراکنش‌هایش سازگار می‌ماند.

**قیمت‌گذاری.** سبد خرید فقط *انتخاب‌ها* را در کوکی نگه می‌دارد، نه قیمت را.
هر بار قیمت از کاتالوگ زنده محاسبه می‌شود (`src/lib/pricing.ts`)، پس دستکاری
کوکی نمی‌تواند قیمت را تغییر دهد.

**پرداخت.** درگاه فعلاً شبیه‌سازی‌شده است. تنها نقطه‌ای که یک فاکتور
پرداخت‌شده می‌شود `settleInvoice()` در `src/lib/orders.ts` است — این تابع
idempotent است و در یک تراکنش، کیف پول، وضعیت سفارش، ساخت سرویس‌ها و تمدید را
انجام می‌دهد. برای اتصال درگاه واقعی کافی است پس از callback موفق همین تابع
با `method: "GATEWAY"` و شماره پیگیری واقعی صدا زده شود.

**رمز سرورها.** رمز root با AES-256-GCM و کلید `CREDENTIAL_SECRET` رمزنگاری
و ذخیره می‌شود (`src/lib/crypto.ts`)، پس یک دامپ دیتابیس به‌تنهایی رمزهای
مشتریان را لو نمی‌دهد. **توجه:** تغییر این کلید، رمزهای ذخیره‌شده را
غیرقابل‌بازیابی می‌کند.

**احراز هویت.** رمز با bcrypt هش می‌شود و سشن یک JWT امضاشده در کوکی
`httpOnly` است. نقش و وضعیت فعال بودن در هر درخواست از دیتابیس خوانده می‌شود،
پس غیرفعال کردن یک حساب بلافاصله اثر می‌کند.

**تاریخچه سفارش.** هر قلم سفارش یک کپی ثابت از مشخصات پلن (`planSnapshot`)
نگه می‌دارد تا ویرایش بعدی کاتالوگ، تاریخچه خرید مشتری را بازنویسی نکند.

## ساختار پروژه

```
install.sh             نصب یک‌خطی (clone، نصب، دیتابیس، seed، اجرا)
prisma/
  schema.prisma        مدل داده (۱۷ مدل)
  seed.ts              داده‌های اولیه: پلن‌ها، لوکیشن‌ها، بلاگ، حساب‌ها
src/
  proxy.ts             مسیریابی زبان (ریدایرکت به /fa یا /en)
  i18n/                fa.ts، en.ts و پیکربندی locale
  lib/
    db.ts              کلاینت Prisma
    auth.ts            هش رمز، سشن، requireUser / requireAdmin
    crypto.ts          رمزنگاری اطلاعات سرور
    pricing.ts         قیمت‌گذاری سبد و اعتبارسنجی کد تخفیف
    orders.ts          ساخت سفارش/فاکتور، تسویه، دفتر کیف پول
    billing.ts         دوره‌های پرداخت و تخفیف‌ها
    settings.ts        تنظیمات سایت
  app/[locale]/
    (صفحات عمومی)/    خانه، پلن‌ها، بلاگ، سوالات، تماس، درباره
    cart، checkout      سبد خرید و تسویه
    dashboard/         پنل کاربری
    admin/             پنل مدیریت
  components/          کامپوننت‌های مشترک
```

## استقرار با داکر

```bash
docker compose --profile full up -d --build
```

پیش از این کار `AUTH_SECRET` و `CREDENTIAL_SECRET` را در محیط تنظیم کنید،
و رمز PostgreSQL را در `docker-compose.yml` عوض کنید.

## قدم‌های بعدی

این نسخه تحویل سرور را **دستی** (توسط ادمین) انجام می‌دهد. برای خودکارسازی:

- اتصال به API هایپروایزر (Proxmox / Virtualizor / Hetzner) در نقطه‌ای که
  `settleInvoice()` سرویس‌ها را با وضعیت `PENDING` می‌سازد
- درگاه پرداخت واقعی (زرین‌پال، نکست‌پی) — فقط یک route برای callback و
  صدا زدن `settleInvoice()`
- کرون تمدید خودکار برای سرویس‌هایی که `autoRenew` دارند
- ارسال ایمیل/پیامک هنگام تحویل سرور و نزدیک شدن به انقضا
